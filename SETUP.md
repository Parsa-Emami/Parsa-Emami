# Profile source

[فارسی](SETUP.fa.md)

The README retains an attributed archival view of the [personalized GitSkins reference](https://www.gitskins.com/portfolio-templates/seyi-editorial/standalone/?username=Parsa-Emami): the architectural hero, Open Sauce typography, lime labels, archival project cards, public repositories, activity, interests and contact. The primary visible section now promotes six evidence-linked, curated engineering projects instead of treating the historical image snapshot as today's featured work. The desktop hero captures the rendered reference. Other sections are self-contained SVGs with Open Sauce glyph paths; mobile versions use narrower layouts. Both GitHub themes keep the reference's dark appearance. The separate Pages mirror retains its own templates and palette.

`data/profile.json` supplies the public content and both color palettes. The builders produce `README.md`, responsive SVG cards and the static `site/` directory. Edit the source data or templates, then rebuild; generated output is replaced on the next build.

`data/readme.json` selects the reference presentation; `data/seyi-reference.json` stores its copy, project order, cached counts, capture date and credits. README and card builders use `load_readme_profile()`; the site builder uses `load_profile()`. The README keeps a visible bilingual identity, official links and six status-qualified engineering projects above the original visual archive. This text is generated by `scripts/build_readme.py` from the profile data and remains visible without expanding the credits. Scheduled rebuilds preserve it. The previous palette and additional-project settings remain available to the legacy card builder. Counts are deliberately frozen to the captured GitSkins source and are not live GitHub totals.

## Local workflow

```sh
python -m venv .venv
.venv/bin/python -m pip install -r scripts/requirements.txt
.venv/bin/python scripts/build.py
.venv/bin/python -m unittest discover -s tests -v
node --test tests/theme.test.cjs
.venv/bin/python -m http.server --directory site 8000
```

Python 3.12 and Node 22 are used in CI. Linux needs FreeType with RAQM for Pillow font rendering (`libraqm0` on Ubuntu). Node is only needed for the theme interaction tests; the published site has no runtime dependencies.

Use `--only cards`, `--only readme` or `--only site` for a targeted build. Cards also rebuild the reference vectors. Add `--fetch` to refresh the separate contribution snapshot; offline builds reuse `data/contributions.json`. `--only site` generates its own artwork and can run independently.

Organizational product descriptions, interfaces and internal architecture are excluded from public output. Project status is editorial content: update it when the source repository changes.

The hero opens the canonical portfolio. Ten original reference visuals and their source-project links are retained inside an expandable archive with the original date and design credits. The six current featured projects are selectable text above the archive, not historical engagement statistics. Mobile graphics are selected below 640px. GitHub cannot run the original video, scrolling, hover, live clock or clipboard scripts in README markup. Keep the captured hero image and JSON snapshot consistent when updating identity or reference content. Source images must be recaptured separately; builds do not contact GitSkins. See `NOTICE.md` for original design and asset attribution.

## Automation

`Update profile` refreshes contribution data, rebuilds, runs Python and theme tests, and commits generated changes including the reference vectors. It runs daily, on demand and after source changes on `main`. It requires `contents: write` and standard `GITHUB_TOKEN`; no new secret is needed. The contribution collector does not change reference counts.

`Deploy site` publishes `site/` through GitHub Pages. Pages must already use **GitHub Actions** as its source. The Pages mirror keeps `https://parsaaemm.dev/` canonical and sends `noindex,follow`. It does not replace the live canonical website.

The activity graphic combines configured public calendars with public repository commit signals per day. It is labeled as an activity snapshot rather than GitHub’s official contribution total. If all sources fail, the collector preserves the previous snapshot.

## Professional GitHub identity (Phase 02)

Curated featured project IDs and role availability live in `data/readme.json`,
not in the historical `data/seyi-reference.json`. Source, status, and
technical evidence are shown directly in the visible README. The old reference
graphics remain an explicitly dated archive under a disclosure; only the hero
is prominent. The generator intentionally continues using local assets
without fetching a third-party design service.

Check the output locally with FOSS Python standard-library tools:

```sh
python scripts/build.py --only readme
python tools/verify_profile_links.py
python -m unittest discover -s tests -v
git diff --exit-code -- README.md
```

The link checker validates URL syntax, safe schemes, local assets, and
non-executable markup offline. It does not assert external HTTP availability.
Account-level Name, Bio, Website and pinned repositories are separate settings
and require owner UI access. See
[Phase 02 account-side acceptance](docs/PHASE_02_GITHUB_IDENTITY.md).
